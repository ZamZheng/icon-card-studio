# GPT → Notion → 云端排版 → Notion

## 首次配置

1. 用户在配套私有素材上传页保存Logo原文件。该页R2持久化，保存文件摘要和原始文件下载路径；替换Logo会创建新摘要文件，旧文件保留。
2. 当前Logo已在用户授权的工具建设中取回、核对摘要并固定为assets/brand/icon-logo.v1.png；日常直接使用随包资产，无需登录素材Site。未来上传的候选不自动替换固定版本。若需读取新上传原文件，执行者使用授权私有Site访问；读取受阻如实报告，不改成公开。
3. 使用处理好的肖像完成首张视觉验收，再固定工具版本。未取得Logo/肖像时可以做明确标记的工程诊断，不交付冒充正式成品的图片。

## 每期生产约定

1. 读本工具规则和目标Notion记录，按栏目+期数唯一定位。新工具风格显式指定为ICON蓝白固定版；旧工具SOP不自动套用。
2. 读取本期已确认标准文案和可访问肖像。若还只是素材，则先形成可阅读标准稿并等待文案确认；已有明确确认稿无需重复确认。原始材料不覆盖。
3. 保留人工医学审核状态，组织成schemaVersion=1的临时JSON，按知识点语义选择登记图标。3/4条依内容决定；标题、引导语与正文须在容量范围内。必要的显示换行不改原意。
4. 从固定Git标签获取工具包，安装锁定依赖与Playwright浏览器，使用包内同一版本Logo。临时文案、肖像与所有输出放本任务目录。
5. 直接使用固定背景和母版排版，无每期背景设计/背景确认步骤。先生成预览和报告，再通过检查输出PNG。长文不得删改、截断、缩字或回退旧工具。
6. 将PNG展示给用户，保留最终视觉验收。把选定PNG、对应标准稿及复现包保存到同一期Notion。复现包需作为附件或压缩包持久化，不能只记云任务路径。
7. 回写失败时交付生成文件并说明缺口；不声称已经归档。渲染通过不自动变更医学审核或标记可发布，不自动发布。

## 平台责任

- GitHub：工具源代码、固定Logo、字体依赖、通用素材、测试、软件版本；不累积每期真实文案或肖像。
- 私有素材Site：Logo候选原文件、摘要和版本下载；上传本身不触发GitHub修改，固定版本由工具维护任务接入。
- Notion：每期素材、确认稿、肖像、状态、最终PNG和复现包。
- GPT：连接器读取、结构整理、云端运行、展示、回写与错误说明。
- Node工具：校验、真实字体排版、技术检查、PNG与复现材料生成。它没有Notion API密钥，不代替GPT连接器。

## 可重复生成

新任务取回同一期复现包，检出manifest记录的工具版本（当前 `v0.1.1`，旧样张保留 `v0.1.0`），执行npm ci和浏览器安装，再用包内content.json、portrait和logo运行render。匹配的运行环境应得到相同像素；跨系统/浏览器版本变化可能影响字形栅格，需以报告环境核对。
